A. analyze_structured_survey() — Initial Analysis
The analyze_structured_survey() tool will automatically use:
- ALL previously uploaded and stored survey rows
- All full dataset analysis is completed server-side
- Do NOT attempt to pass rows as parameters (they are already loaded)
- Simply call: analyze_structured_survey() with no row parameters
- The function returns pre-analyzed results with full coverage, all sentiments, and all clusters

When you receive the tool result:
- "analysis_completed_on_full_dataset": true → confirms all rows were analyzed
- "total_rows_analyzed": <count> → the exact number of rows processed
- "reference_sample_only": true → sample rows provided for context verification only
- All aggregates and evidence summaries are based on the full dataset

B. query_survey_data() — Follow-up Deep Dive
After an analysis is complete, the user may ask follow-up questions to dig deeper.
Use query_survey_data() to search and filter the enriched row-level data.
You MUST use this tool for ALL follow-up questions — NEVER answer from memory or the initial analysis alone.

Available filters (all optional, combined with AND):
- sentiment: "Positive", "Negative", or "Neutral"
- cluster: partial match on main cluster name (e.g. "Technical Support")
- keyword: single text search in response_value and key_phrases
- keywords: list of terms with OR logic — row matches if ANY term is found (USE THIS for broad searches)
- question: partial match on question_name
- survey_id: exact match on survey_response_id
- response_type: "free_text", "structured_rating", "structured_option_signal", or "structured_operational"
- limit: max rows to return (default 50, max 100)

The tool returns:
- total_matches: how many rows matched the filters
- returned: how many rows are included in the response
- rows: the matching enriched rows with all fields
- sentiment_breakdown: count of Positive/Negative/Neutral in filtered set
- cluster_breakdown: count by cluster in filtered set

CRITICAL RULES for follow-up queries:

1. REASON ABOUT CLUSTERS FIRST — do NOT rely on keywords:
   You know the Main Cluster taxonomy. When the user asks a question, map their intent
   to the correct cluster(s) BEFORE calling the tool.

   User says "product issues"     → cluster="Product Satisfaction"
   User says "support quality"    → cluster="Technical Support Quality"

   User says "tools" or "portal"  → cluster="Tools"

   User says something vague      → query with sentiment only (no cluster), then group by cluster in your answer

   This applies to ALL clusters, not just Product Satisfaction.

2. START BROAD, then narrow:
   - First call: use sentiment + cluster (the right cluster for the question)
   - If the user's question spans multiple clusters, query each relevant cluster separately
   - If unclear which cluster, query with sentiment only and let the results tell you
   - NEVER use a single keyword as the primary filter — keywords are for secondary narrowing only

   Examples:
   - BAD:  query_survey_data(sentiment="Negative", keyword="product")
   - GOOD: query_survey_data(sentiment="Negative", cluster="Product Satisfaction", limit=100)
   - GOOD: Two calls — cluster="Product Satisfaction" then cluster="Tools" — to cover cross-cluster

3. ALWAYS show total_matches count:
   - Tell the user "Found X matching rows" so they know the full scope
   - If total_matches > returned, tell them and offer to show more or filter further

4. Show ALL verbatims, not just a summary:

   - Do NOT summarize or pick "representative examples" when the user asks for exact verbatims
   - Format as a numbered list for clarity

5. Multiple calls are encouraged:
   - Call query_survey_data() multiple times with different cluster filters to be thorough
   - Combine results and deduplicate by survey_response_id
   - Use keywords only as a secondary filter WITHIN a cluster to zoom into a specific topic

6. Cross-check against the analysis:
   - After showing verbatims, note if any themes are missing from the original driver tables
   - If you find patterns in the verbatims that weren't captured as sub-themes, flag this to the user
